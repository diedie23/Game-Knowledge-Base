TAPD 排期与整体风险工作台优化报告

目标不是增加更多卡片，而是把现有能力收敛成一条可执行链路：数据可信 → 自动预排 → 人工确认 → 推送 TAPD → 风险跟踪与关闭。审查基于当前 V2 实际页面、渲染结果及核心服务代码。

审查日期：2026-10-10范围：交互 / 视觉 / 功能 / 数据读取 / 工程质量目标：更快排期 + 风险闭环

一、结论摘要

基础完整

已有仪表盘、甘特图、排期助手、资源矩阵、需求风险、数据质量、同步中心、What-If 与周报，不需要推倒重建。

链路分散

用户需要在仪表盘、甘特图和同步中心之间跳转；自动建议只应用日期，人员调整和推送仍需二次操作。

口径并存

TAPD 排期助手按并行任务数评估冲突，另一套排期服务按日产能与人天计算，风险与容量可能给出不同结论。

二、当前能力与主要断点

当前已具备

  • 多 TAPD workspace 拉取、字段映射、稳定远端身份与本地缓存。
  • 待排任务识别、岗位匹配、依赖避让、45 天时段搜索、批量场景预占容量。
  • 任务级风险、UIStory 需求级风险、两周岗位容量与数据质量审计。
  • 甘特拖拽、风险面板、快照、What-If、撤销重做及待推送日志。

关键断点

  • 仪表盘信息纵向过长，决策项与日常状态同权排列。
  • 排期助手与需求风险都只展示前 8 项，不能作为完整处理队列。
  • 建议人员与日期现已同步应用到本地待推送队列；但“应用并直接推送 TAPD”仍需在同步中心二次确认。
  • 风险只能被发现，缺少负责人、动作、截止日、状态和关闭记录。
  • 刷新曾在页面进入时静默执行，失败后用户仍可能基于旧缓存做决策。

三、已直接完成的 P0 一致性修复

本轮已落地并通过验证：统一聚合身份、补齐导入隔离、修复甘特项目配置读取，并增加仪表盘数据刷新状态提示。
修复项处理结果价值
统一任务逻辑身份新增 getTaskIdentity()，优先使用 syncId，其次使用 workspaceId + tapdId，旧数据按项目隔离。避免不同 workspace 相同数字 ID 在排期、周报、负载和风险中被错误合并。
数据质量重复检测由纯 tapdId 分组改为稳定身份分组，并新增跨 workspace 回归测试。消除“跨工作区误报重复”的关键错误。
CSV/预览导入配置按当前项目读取；单 workspace 时写入 tapdWorkspaceId 与 syncId；多 workspace 不再猜测归属；匹配限制在当前项目。避免导入任务写入其他项目或与其他 workspace 任务错误覆盖。
甘特 TAPD 配置由读取数据库第一条配置改为读取当前选中项目配置。项目切换后按钮状态和刷新目标保持一致。
排期方案落库单项与批量应用都同时写入建议人员、开始日期和结束日期。确保推荐方案与实际待推送内容一致。
刷新透明度仪表盘显示“刷新中 / 成功 / 失败并使用缓存”，失败可直接进入同步中心。减少在数据过期或刷新失败时误判排期。

四、推荐的核心用户流程

1. 拉取与校验
增量同步、字段映射、身份去重、质量门禁
→
2. 生成预排方案
统一容量、依赖、截止日、技能和请假口径
→
3. 批量确认
人员 + 日期 + 工时同时确认，低置信项单独处理
→
4. 差异预览
展示人员变化、延期影响、负载变化与字段写回清单
→
5. 推送与闭环
按项目推送 TAPD，失败可重试，生成风险动作

五、首屏信息架构：从信息汇总页改为决策工作台

区域建议内容交互原则
顶部可信度条最后成功同步时间、覆盖 workspace、拉取条数、失败条数、待推送数、数据可排期状态。任何失败均可展开原因与重试，不用打开控制台。
核心 KPI待排任务、可自动排、需人工确认、关键风险需求、未来两周容量缺口、里程碑预测偏差。点击即过滤下方队列。
主工作区默认展示“排期队列”，可切换“风险驾驶舱”和“数据问题”。完整分页/虚拟列表，不截断为前 8 条。
右侧上下文选中任务的父需求、依赖、候选人员、日容量热力、推荐理由和字段差异。无需离开页面即可确认。
底部固定操作栏已选数量、可应用数量、需确认数量、预计延期、应用本地、应用并推送。高风险与低置信项默认不可批量自动推送。

六、统一排期内核

P0 架构问题：tapdPlanningAssistant.ts 与 schedulingService.ts 是两套排期算法。前者以并行任务数为主，后者使用日产能、人天与 WIP。应合并为同一计算内核，所有页面只消费同一份 ScheduleScenario。

统一输入

  • 任务稳定身份、工作量、阶段、优先级、截止日、状态、依赖。
  • 人员岗位、技能、每日有效工时、WIP、请假、供应商类型。
  • 项目日历、节假日、里程碑、冻结区间。
  • 缺失工时不得无提示默认为 2 天；改为岗位中位数并标记“估算值”。

统一输出

  • 人员、开始/结束日期、每日分配工时。
  • 置信度及可解释原因。
  • 相对当前基线的延期天数、峰值负载与受影响需求。
  • 硬约束违规、软约束代价和人工确认原因。

七、风险驾驶舱与闭环模型

风险维度

  • 交付：逾期、截止日预测、关键路径、里程碑偏差。
  • 依赖：前置未完成、跨管线卡点、循环依赖。
  • 资源：每日超载、WIP 超限、单点人员、岗位容量缺口。
  • 执行：进度落后、长时间未更新、阻塞持续时长。
  • 数据：重复、父子断链、字段缺失、同步过期、人员未映射。

风险实体需要补齐

  • riskId、风险类型、来源任务/需求、严重度与影响天数。
  • 责任人、协同人、处理动作、目标日期。
  • 状态：新建 → 已确认 → 处理中 → 待验证 → 已关闭 / 已接受。
  • 首次发现、最近变化、关闭时间、关闭依据。
  • 每次同步保留风险快照，展示新增、升级、缓解、关闭趋势。

八、数据读取与同步优化

优先级建议实施要点
P0统一身份贯穿所有入口API 拉取、CSV 导入、数据质量、工作量、排期、周报、风险均只使用统一身份函数；禁止新增纯 tapdId 全局匹配。
P0同步快照与质量门禁每次同步记录项目、workspace、范围、数量、耗时、成功/失败和错误；数据不新鲜或关键异常时禁止一键推送排期。
P1真正的增量读取按项目/workspace 记录 cursor 或 modified 时间；定期做低频全量校验，避免只靠时间窗口遗漏删除或回写。
P1部分失败可恢复多 workspace 并行拉取；单 workspace 失败不丢弃其他结果；失败批次支持从断点重试。
P1项目级查询与缓存减少全表 toArray()；任务、资源、日志查询尽量使用项目索引；复用风险与容量计算上下文。
P2可审计同步提供字段级变更历史、来源、操作者、冲突选择与推送回执。

九、交互与视觉规范

降低密度

甘特工具栏保留日期、搜索、筛选、风险与刷新；快照、导出、密度、项目状态归入“更多”。侧栏支持折叠，释放排期横向空间。

建立层级

一个页面只保留一个主操作。首屏突出“生成预排 / 确认并推送”，次要数据用可展开区域，不让所有卡片争夺注意力。

统一状态语言

红色仅表示阻断/严重风险，橙色表示需关注，蓝紫表示推荐/操作，绿色表示健康/完成；状态需同时有文字，不能只依赖颜色。
