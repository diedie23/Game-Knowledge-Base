🖥️ 二、UI 发包标效细化 重点补全

UI 发包不能只用"一套界面"笼统报价。切图按张、图标按套、UMG 拼接按界面×状态数，才能算准。以下为 UI 特有的发包评估维度。

2.1 UI 按交付物类型的发包标效

交付物类型计量单位基准标效发包备注
界面视觉设计（含切图导出）按界面复杂度 S/A/B/C见上表 UI 行核心界面建议内制，次级/弹窗可发包
切图 / 资源导出按张0.05~0.15d/张规则清晰可批量；含九宫格标注、命名合规
图标绘制按套（10~20个）2~4d/套技能/道具/货币图标；风格统一是关键
UMG / UGUI 拼接按界面 × 状态数0.5~1.5d/界面状态多、动效多则×1.5；建议内制或强规范外包
UI 动效按界面1~3d/界面依动效复杂度；纯程序动效可不发包给美术
本地化适配按语言 × 界面0.2~0.5d/界面/语言长文本/RTL 语言需额外布局验证

2.2 UI 发包量化速算

UI 发包工作量 ≈ Σ(界面数 × 界面标效) + Σ(切图张数 × 0.1d) + Σ(图标套数 × 3d) + Σ(拼接界面 × 状态系数)
💡 示例：发包"商城模块" = 1个A级界面(4d) + 3个B级弹窗(3×1.5d) + 1套货币图标(3d) + 切图约40张(4d) ≈ 15.5 人天。按 UI 设计 ¥800~1200/天（二线CP）计，约 ¥1.2万~1.9万。

🎯 四、效率度量指标（统一口径）

标效不只是"估多少"，还要"回头看准不准、做得快不快"。以下为统一的效率度量口径，避免各文档各说一套。

指标公式 / 定义健康基准
排期准确率1 − |实际人天 − 预估人天| / 预估人天≥ 80%
一次通过率首次提交即验收通过的资产占比≥ 70%
平均返工轮次资产从提交到通过的平均打回次数≤ 2 轮
外包一次通过率外包首件/批量首次验收通过率≥ 60%（磨合后≥80%）
让步接收率让步接收的交付批次占比< 20%（超则供应商观察）
人均日产能标准化资产当量 / 有效人天按团队历史基线

🧭 五、怎么用 & 怎么校准

使用姿势

  • 内部排期：查工种×复杂度 → 得基准人天 → 乘团队校准系数 → 加缓冲。
  • 发包报价：查基准人天 → 套报价公式（×单价×复杂度×风险）。
  • UI 发包：先拆交付物（界面/切图/图标/拼接）→ 用第二节分项算 → 汇总。
  • 回头复盘：用第四节指标核对预估 vs 实际，反哺校准系数。
⚠️ 数据前提与失效提醒：本页数值基于 2026 年中大型手游（含二次元/MOBA/RPG） 实战区间，币种为人民币。适用前提：① 团队为成熟工业化管线；② 每季度用"预估/实际"比值校准一次；③ 预研期高不确定性资产，风险系数上限 2.0 可能不够，建议单列探索缓冲。脱离前提直接照搬会失真。
🔗 权威源分工：基准人天与报价公式以 outsource-workload-model 为准；人月成本与 ROI 以 cost-standard 为准；本页为汇总总表并补全 TA/音频/UGC/UI 细化。三者数值如有冲突，以各自权威源为准并回报更新本页。
