📦 一、外包验收判定 — 打回 / 让步接收 / 接收

外包PM每天纠结的核心：交付物没达到满分，但砍了重做又赶不上排期。用红线代替"感觉差不多"。

🚦 三档量化红线

🔴 必须打回重做
  • 面数 / Drawcall 超预算 > 30%
  • 贴图规格错误（尺寸、通道、命名）≥ 3 处
  • 骨骼层级 / 绑定结构与规范不符，无法直接入引擎
  • 核心视觉与原画偏差明显（角色识别度受损）
  • 出现版权 / AIGC 合规风险素材
🟡 让步接收（限时补救）
  • 面数 / Drawcall 超预算 10%~30%，且非性能敏感场景
  • 色差 ΔE 3~6，非关键氛围资产
  • 命名 / 目录不规范但不影响功能（可脚本批量修）
  • 次要部件精度不足，主体达标
  • ➡ 条件：签让步单 + 限X天补齐 + 结算扣款/记录
🟢 直接接收
  • 面数 / Drawcall 在预算 ±10% 内
  • 色差 ΔE < 3（肉眼几乎无差）
  • 命名、目录、格式全部符合规范
  • 首件已验、批量抽检合格率 ≥ 95%

🌳 验收决策树

Q1 有无合规 / 版权 / 无法入引擎的硬伤？
✅ 有 → 无条件
🔴 打回，不进入后续判断
❌ 无 → 进入 Q2
Q2 技术指标（面数/贴图/骨骼）超标幅度？
> 30% 或 结构性错误
🔴 打回重做
10%~30% 且可后期优化
🟡 进入 Q3 判断是否让步
< 10%
🟢 进入 Q4 最终抽检
Q3 该资产是否处在性能/视觉敏感位（主角、高频、近景）？
是 — 敏感资产
🔴 打回（敏感位不接受让步）
否 — 次要资产 + 排期紧张
🟡 让步接收 + 签让步单 + 限时补救 + 结算扣款
Q4 批量抽检合格率 ≥ 95%？
是
🟢 接收入库
否（80%~95%）
🟡 退回不合格件返修，合格件先入库
⚠️ 让步接收不是"放水"：每次让步都必须留痕（让步单 + 扣款/评分记录）。让步率是评估 CP 的关键指标，季度让步率 > 20% 的供应商应进入淘汰观察名单。

外包PM
技术指标判定、常规让步/打回，直接执行
主美
视觉品质争议、核心资产的最终审美裁定
制作人
让步涉及品质底线、或影响里程碑时的最终拍板

🐛 二、Bug 定级争议仲裁 — "算不算 bug、算几级"

"美术说是设计如此，QA说是缺陷"——这类争议最耗人。定级看客观影响，不看主观立场。

🚦 定级量化标准（客观影响优先）

等级客观判定标准响应时限
S / 阻断崩溃、黑屏、资产丢失、无法进入关卡、送审必挂当天
A / 严重核心角色/主界面明显穿模、错位、闪烁；付费点视觉异常1~2 天
B / 一般非核心资产瑕疵、边缘视角可见、不影响核心体验本迭代内
C / 轻微极端条件才可见、审美倾向类、优化建议排期允许时

🌳 "算不算 Bug" 仲裁决策树

Q1 是否偏离已签署的规范 / 需求单 / 原画？
是 — 有明确文档依据
🔴 判定为 Bug，按客观影响定级
否 — 无文档，属主观审美/体验争议 → Q2
Q2 是否影响玩家可感知的核心体验或送审？
是
🟡 记为"体验优化项"，主美 + 制作人评审优先级
否
🔵 记入 backlog（C 级），不阻塞版本
Q3 双方仍无法达成一致？
升级仲裁
⚖️ 主美裁定"是否偏离预期" + QA主管裁定"定级"，制作人对送审级争议终裁
🎯 反扯皮原则：先问"有没有白纸黑字的依据"。有依据 → 客观定级；没依据 → 这不是 bug 争议，是"需求没写清"的流程问题，应回溯补规范，而非在群里吵。

⚖️ 谁拍板

QA
依标准初判定级，登记 issue
主美
"是否偏离美术预期"的裁定
制作人
送审级(S)争议、上线卡点的终裁

⏳ 三、延期止损决策 — 砍量 / 延期 / 加人 / 降标准

发现要延期时，慌乱加人往往越帮越忙。先算清偏差量级，再从代价最小的手段依次选。

🚦 触发红线（偏差多少该动手）

燃尽偏差信号动作
< 10%🟢 正常波动观察，周会同步，不额外动作
10%~20%🟡 黄色预警本周内定位瓶颈 + 内部消化（调优先级/微调分工）
20%~35%🟠 橙色预警启动止损决策树，上报制作人，出 Plan B
> 35%🔴 红色告警里程碑重排，砍量/延期二选一，全员对齐

🌳 止损手段决策树（按代价从低到高）

Q1 是否有"锦上添花、砍掉不影响核心体验"的内容？
有 — 优先级最低成本
🟢 砍量 / 降规格（首选，代价最低）
无 → Q2
Q2 剩余工作是否可拆分、能被新人快速接手？
能 且 有可靠外包/机动人力
🟡 加人/外包分担（注意沟通与磨合成本，最晚不超过剩余工期的 60% 节点）
不能（强依赖核心人 / 难拆）→ Q3
Q3 该里程碑是否为对外硬节点（发行/送审/买量）？
是 — 不能延
🔴 降标准保节点（降精度/占位过审），并登记技术债后续补
否 — 可协商
🔵 申请延期（给出新排期 + 根因 + 防复发措施）
🧨 Brooks 定律提醒："向进度落后的项目盲目加人只会让它更慢"。加人窗口越晚越无效——过了剩余工期 60% 节点还想靠加人救火，通常只会增加沟通成本。此时应转向砍量或降标准。

⚖️ 谁拍板

PM
10%~20% 内部消化，自行处置
制作人
砍量、降标准、加预算的决策
发行/项目负责人
对外节点延期、里程碑重排的最终确认

📝 四、需求变更成本评估 — "改这版到底多贵"

口头一句"稍微改改"，落到已完成资产上可能是几人天 + 排期连锁反应。用速算器把成本摆到台面上再决定。

🚦 变更放行红线

🟢 PM 可直接放行
  • 成本 < 2 人天 且不影响里程碑
  • 资产处于草稿/制作早期
  • 无连锁影响，独立可控
🟡 走 CR 评审
  • 成本 2~5 人天 或触碰当前 Sprint 缓冲
  • 影响已完成资产 / 少量关联
  • ➡ 填变更单，评估后制作人签字
🔴 冻结期原则不接
  • 成本 > 5 人天 或冲击里程碑
  • 影响整套资产 / 风格基线
  • 处于量产冻结期 / 封版前
  • ➡ 除非制作人拍板并同步顺延排期
✅ 落地话术：面对"随口加需求"，不要说"不行"，而是说"可以，这版改动约 X 人天，会占用 Y 天排期，需要走个变更单让制作人确认下优先级"。把成本可视化，决策权自然回到该拍板的人手里。

⚖️ 谁拍板

PM
< 2 人天的低风险变更
制作人 + 策划负责人
CR 评审，优先级与排期让路的决定
主美
涉及风格基线/整套资产的变更评估
